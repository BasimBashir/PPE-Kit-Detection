# Phase 3 log: vest, gloves, goggles, safety shoes (plans, results, what failed, what replaced it)

Decision record: [ADR-014](../decisions/ADR-014-multi-ppe-rules.md). Every number below is generated by a script
in this repo; per-class JSON next to this file. Dates: 2026-11-20.

## 1. Data: what exists publicly and what we used

| Source | Images | Classes we need | Licence | Used? |
|---|---|---|---|---|
| Ultralytics **Construction-PPE** (current release) | 1,000 (800 train / 200 val), 1264-2048 px | helmet, vest, gloves, boots, goggles **and** no_helmet / no_vest / no_gloves / no_boots / no_goggle | CC BY 4.0 | yes - primary; its 200 val images are our **test** split (never trained on) |
| HB1204/PPE_Detection (Roboflow export, Hugging Face) | 3,086 (2,717 / 115 / 254) | same items + NO-Hardhat / NO-Safety Vest / NO-Gloves / NO-Goggles; **no "no boots"** | CC BY 4.0 | plan C (added to training) |
| SH17 (Pexels, manufacturing) | 8,099, up to 8K px | gloves, shoes, glasses, safety-vest + bare hands / foot / head / face | CC BY-NC-SA 4.0 (non-commercial) | downloaded as a reserve; not used (see 5) |
| Hard Hat Workers (Phase 1) | 5,000 | helmet / head | CC0 | unchanged - still trains the helmet stack |

The ultralytics package's bundled `construction-ppe.yaml` still describes an older 1,416-image / 11-class release;
the archive it downloads is the current 1,000-image / 12-class one (adds `no_vest`, `forklift`). We trust the
archive's own `data.yaml` + README, not the bundled yaml.

Unified 10-class schema (`scripts/dataset/prepare_multippe_dataset.py`): helmet, no_helmet, vest, no_vest, gloves,
no_gloves, goggles, no_goggles, boots, no_boots. Person/forklift/"None" dropped (the pose model finds people).
"No_*" means **the body region is visible and bare** (the dataset README states the same convention) - exactly the
ABSENT evidence the Phase 1 associator needs; occlusion is never ABSENT.

Test split = Construction-PPE official val (200 images: 179 no_helmet, 130 no_vest, 203 no_gloves, 82 no_goggles,
178 no_boots boxes). Validation for early stopping = a seeded 12.5 % of Construction-PPE train.

## 2. Plans tried (detector for the four new items; helmet classes reported for reference only)

| Plan | Data | Model / input | mAP50 (test) | no_vest | no_gloves | no_goggles | no_boots | Train | Result |
|---|---|---|---|---|---|---|---|---|---|
| A | Construction-PPE | yolo26s / 640 | 0.802 | 0.765 | 0.726 | 0.491 | 0.796 | 12 min | baseline: items found well (vest 0.96, goggles 0.96), **bare-region classes weak** |
| B | Construction-PPE | yolo26m / 1280 | 0.838 | 0.819 | 0.755 | 0.634 | 0.796 | 40 min | resolution wins: bare-region classes jump (no_goggles +0.14) |
| C | + HB1204 (3,086 imgs) | yolo26m / 1280 | **0.851** | 0.813 | 0.755 | 0.674 | 0.811 | 116 min | **installed**: best on the held-out Construction-PPE test |

Plan C also evaluated on the **HB1204 test split** (its train/valid were in C's training data, test was not):
mAP50 0.557, no_gloves **0.06**, no_goggles 0.17 - the two datasets label bare regions with different box
conventions, and a model tuned to one convention transfers poorly to the other. C is chosen because the
Construction-PPE val (our consistent-convention test, never trained on) is what the ABSENT-evidence matcher
relies on; the transfer gap is a real risk flag: **expect a site-data fine-tune to be required** before
production accuracy claims, exactly the operator-confirmed-label path Phase 2 already built.

Per-class JSON: `docs/ml/multippe_<plan>_eval.json`.

**Why A was not enough.** Recall on the bare-region classes (no_goggles 0.44, no_gloves 0.61, no_helmet 0.65)
decides whether a violation is ever seen; precision is already high (0.74-0.91). Eyes and hands are a few percent
of a 2048 px image, i.e. a handful of pixels after the 640 px letterbox.

## 3. Pipeline (what changed, what did not)
Same cascade as Phase 1 (ADR-014): pose -> helmet detector (unchanged) + items detector (new, same batch) ->
tracker -> per-rule association on the item's body region -> N-of-M state machine -> event/outbox. Unit tests:
`backend/tests/unit/test_multi_ppe.py` (bare hand beats gloved hand, vest on the ground not credited, no wrist
keypoints = UNCERTAIN, feet cut by the frame = UNCERTAIN, presets validate, every item has a teacher question).

## 4. High resolution (4K) streams
measured - see [docs/benchmarks/phase3-4k.md](../benchmarks/phase3-4k.md): 10 x 4K@25fps CPU-decode 12.6 fps
(host 92%) -> NVDEC + resize-once + preview-shrink 20.7 fps (host 57%); sizing tables for 5 fps and full 25 fps
inference; network sharding (`PPE_WORKER_SHARD`).

## 5. Not used / rejected
- **SH17** - largest, highest-resolution set, but CC BY-NC-SA (non-commercial) and a different absence convention
  (bare hands/feet/heads are separate classes, not "no_gloves"); kept as a reserve for the hands/feet regions if
  plan C still misses too many bare hands.
- **One detector for all five items incl. helmet** - see ADR-014 alternatives.
